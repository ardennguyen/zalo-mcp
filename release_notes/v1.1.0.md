## zalo-mcp 1.1.0

> Proposed release notes. Requires upstream branch `v1.1.0`, an engine release
> containing engine PRs #2/#3/#4, a regenerated lockfile and passing install/CI
> checks. The wrapper PR is still draft. No tag or release has been created.

Select an account from your MCP client, and accept compatible engine 2.x
releases with `@ardennguyen/zalo-agent-cli` **^2.0.1** instead of fixed 2.0.0.

### Highlights

- **Forward `--account <ID>` or `--account=<ID>`.** Use the full numeric string
  ID from the engine's account list. IDs are never converted to JavaScript
  numbers. Invalid, missing or duplicate values fail before installation/login.
- **Keep engine behavior authoritative.** The engine selects credentials, owns
  the account lock, and pins reconnects. Omitting the flag keeps engine defaults.
  An older engine rejecting the flag fails; the wrapper never retries as the
  active account.
- **Compatible engine updates.** `^2.0.1` accepts 2.x releases below 3.0.0.
  The lockfile still selects an exact installed version; an existing install
  is not updated simply by changing the range.

### What the new engine brings

When the installed engine includes engine PRs #2/#3/#4:

- Current sender names prefer your alias, then Zalo profile name, then UID;
  historical message names are preserved. Sync also refreshes cached 1-1 names.
- Account pinning survives reconnects and retries.
- **14 MCP tools**: `zalo_sync` requests message/reaction sync and
  `zalo_sync_status` reports progress/results. Message restore still needs a
  phone tap. Jobs use the existing daemon socket and stage lock.

### Upgrade

After publication:

```bash
bash zalo-mcp.sh update     # Linux / macOS
.\zalo-mcp.ps1 update       # Windows
```

Then add `"--account", "101"` after the launcher path in the MCP client's args
and restart the client. `101` is a synthetic example; substitute your registered
account ID. Use distinct IDs for separate processes. Never run npm install by
hand in an existing deployment.

### Things to know

- Requires Node.js 22 or newer (the engine needs 22.19+ in practice).
- Forwarded options are `--http`, `--auth`, `--account`. Other engine flags,
  including `--host` and `--config`, still require invoking the engine directly.
- As of 2026-10-15 npm latest is engine 2.0.0; ^2.0.1 currently returns ETARGET.
  Publish the engine first, generate the real wrapper lockfile, and verify it
  installs an engine containing these features before releasing this wrapper.
- Launcher tests are offline. Live account reconnect and phone restore remain
  unverified by this contribution. Existing local deployments are unchanged.
